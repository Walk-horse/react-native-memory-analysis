采集步骤

  1. 启动后立即自动拍一张基线快照，此刻 App 会卡顿 10~15 秒，属正常。
  2. 然后进入等待：在 App 里走一遍「进入详情 → 滚动 → 返回」，回到这里点拍下一张快照。
  3. 重复相同路径再做一轮，最后一次点击后自动分析并出报告。
  4. 全程不要锁屏、不要把 App 切后台，否则 inspector 会断连。

可配置多个模型，分析中按需选择用哪一个（默认模型用于未指定时）。每个模型的 Base URL / 密钥独立保存，生成参数（温度、超时、提示词、深度分析）为所有模型共享。

生成参数

候选条数决定送给模型的报告体量；提示词可自定义分析口径。

模型只要持续输出就不会被中断：「空闲超时」只在连接、等待首个响应或连续静默时生效，每收到一个数据块就重新计时；「总时长上限」是防止上游无限慢速输出的兜底，设 0 不限制。本机解析快照与源码的时间不计入这两项。

深度分析（保留快照时）

采集时勾选「保留快照文件」后，AI 会额外参考本机解析的原始快照结构与项目源码片段。

配置说明

  • 配置文件：-（权限 0600）。API Key 只写本地文件，浏览器拿到的一直是掩码。
  • 环境变量优先级高于文件：HEAPSCOPE_AI_BASE_URL、HEAPSCOPE_AI_API_KEY、HEAPSCOPE_AI_MODEL、HEAPSCOPE_AI_CONFIG。由环境变量提供的字段只读，保存文件不会覆盖它。
  • 本地模型（Ollama 等）可以不填 API Key；任何其他地址都需要密钥才能调用。
  • 默认只送报告摘要（meta / 堆趋势 / 候选 top N / 源码位置 / 持有链 / 警告），不含原始 .heapsnapshot，也不含 API Key。
  • 深度分析：采集时勾选「保留快照文件」后，HeapScope 会在本机解析快照（逐轮构造器、新增对象、候选精确 GC root 持有链）并读取项目源码片段，只把压缩后的证据文本追加到 prompt。原始快照与完整源码文件不会上传。
  • 源码读取限制在项目根目录内；.env / 密钥类文件会被跳过，片段中的密钥样式字符串会脱敏；证据总量受字符上限裁剪，大快照可设大小上限跳过。
  • 项目源码来自当前工作区，可能与采集时的 bundle 不一致；报告里的「源码指纹」异常会作为警告一并送给模型。
  • AI 结论属于启发式推断，不是泄漏证明；请结合快照与源码人工复核。
